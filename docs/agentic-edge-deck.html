BLUF · agentic workloads on edge silicon

The agent's brain is bandwidth-bound, not TOPS-bound.

Measured on four devices from an RTX 5090 to a Neutron-class NPU: an on-device agent's cost is set by memory bandwidth, CPU, and model size — not by the TOPS number on the box. That changes how you size an edge-AI product.

01

Generation rides on bandwidth

Token decode is memory-bandwidth-bound. Across 4 boards, decode tok/s tracks DDR bandwidth, not TOPS. Confirmed independently on a Hexagon NPU, three ways. measured

02

The NPU earns its area on perception

The accelerator pays off on vision/ASR and prefill (TTFT) — the perception front-end. The generation loop itself leaves the NPU largely idle. measured

03

Model size ≈ a 2× wall

+1 model tier = ~1.9× decode latency + ~2× memory, and it's architecture-invariant. On the smallest boards the bigger brain doesn't slow down — it doesn't fit. measured

04

So the sizing question flips

"Which model tier can this board hold and feed?" — a bandwidth + capacity question. The TOPS headline is the wrong number to size against. derived

02 / 09

definition · two very different "agents"

Not all "agentic" wants the same silicon.

The word hides a 100× hardware split. Size for the one you're actually shipping.

(a) ships on-device today

Bounded skill-orchestrator

A fixed menu of tools — retrieve, transcribe, summarize, read/write files, call an API. A small on-device LLM (7B-class) is a capable enough brain. This is what Google Gemini Nano and Apple Intelligence actually ship.

(b) wants a frontier brain

Autonomous code-gen / open-ended

Writes and runs novel code, plans open-endedly. Local-first in principle, but needs a large model to be good — today that's a cloud-scale brain, not an edge part.

This deck benchmarks (a) — the shippable case — using a local skill-orchestrator agent ("Skippy", Qwen 2.5 7B) as the reference, grounded in a general agent framework's capability set so the task list isn't cherry-picked.

04 / 09

the core physics

Decode is memory-bandwidth-bound.

Each generated token re-reads the whole model's weights from memory. So generation speed is set by how fast you can stream weights, not by peak math throughput. Prefill (the prompt / first token) is compute-bound and parallel — that's a different resource.

  • Generation-heavy tasks: ~85–90% of time in decode. measured
  • RAG/tool tasks: 51–70% decode, +37–47% in CPU/DDR orchestration. measured
  • Cross-board, decode tok/s tracks DDR bandwidth — not TOPS. measured
independent corroboration — Hexagon NPU

A separate team, measuring Qwen on a Qualcomm Hexagon NPU on completely different instruments, found the same thing:

"Decode is DDR-bandwidth-bound, confirmed three ways. The scarce resource for LLM/VLA decode is DDR bandwidth, not TOPS."

the sizing tradeoff · 7B vs 14B

A bigger brain costs ~2× — and the cost is the same everywhere.

The decode penalty ≈ the parameter ratio, architecture-invariant from datacenter Blackwell to edge Ampere — because decode streams weights, so cost scales with parameter count. measured

and on small boards it isn't a slowdown

It's a wall.

A 14B Q4 (~9 GB) will not fit the NPU's 8 MB VTCM working set — it simply doesn't run. And the deployed NPU bundle caps a single prompt at 256 tokens; longer RAG context falls back to CPU at ~19 tok/s. measured

Sizing an edge agent is first a fit question, then a feed question — capacity and bandwidth, not TOPS.

08 / 09

where the NPU pays off

The accelerator's job is perception, not generation.

The LLM generation loop is bandwidth-bound and leaves the NPU idle. The workloads that are genuinely compute/TOPS-bound — and where a big NPU earns its area — are the perception front-end:

  • Vision / VLM / VLA — image prefill dominates, decode is tiny (the mirror image of the LLM tasks).
  • ASR, and prefill / TTFT generally — parallel, compute-bound.

So an agentic edge SoC wants: enough DDR bandwidth + CPU for the generation loop, and NPU TOPS aimed at perception and first-token latency — two different budgets.

09 / 09

the decision

Size the subsystem, not the TOPS.

The deliverable isn't a benchmark — it's a sizing framework the product team can run: for any agentic feature, decide the model tier, confirm it fits the board's working set, then check the board can feed it at target latency.

recommend

Stand this up on i.MX95 silicon

Move the ladder from emulation + fleet proxies onto real ARA240 silicon, with an accuracy gate (the two-judge pass) wired in. Closes the one remaining measured gap.

design input

Budget DDR + CPU for the loop

Agentic throughput is set here. Point NPU TOPS at perception + TTFT — a separate budget. Don't size the generation loop against the NPU spec.

product rule

Fit-then-feed, per feature

Small boards: a 7B-class orchestrator is shippable and passes most tasks. Bigger brains are a Thor-and-up part — and a hard "won't fit" below.

watch

Context length is the hidden cap

The 256-token NPU prompt cap is the binding constraint for RAG on the smallest board — long context silently falls to CPU. Size RAG against it.
